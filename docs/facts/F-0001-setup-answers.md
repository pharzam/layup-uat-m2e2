3. `Q-002` Combined flags such as -lw are accepted and mean the same as -l -w. The name - is not standard input: tally treats it as a file named -. An unknown flag or wrong usage prints a usage message on standard error, counts nothing, and ends with the exit code 2. — by idea-owner; source https://github.com/pharzam/layup-uat-m2e2/issues/1#issuecomment-6343642161; the question: Must combined flags such as -lw be accepted, is - a name for standard input, and what does tally do with an unknown flag (message and exit code)?
4. `Q-003` The other files are still counted. No row is printed for a file that is not valid UTF-8, and it adds nothing to the total; a message on standard error gives its name, and the exit code is 1 at the end. The check happens while the file is read, before its row would be printed: rows already printed for earlier files stay. — by idea-owner; source https://github.com/pharzam/layup-uat-m2e2/issues/1#issuecomment-6343642161; the question: For a file that is not valid UTF-8, are the other files still counted, is a row (and a share of the total) printed for the invalid file, and does the check happen before or after any counts are printed?
5. `Q-004` The row for standard input has no name: it ends after the counts. — by idea-owner; source https://github.com/pharzam/layup-uat-m2e2/issues/1#issuecomment-6343642161; the question: When standard input is counted, what file name (if any) appears in its output row?
6. `Q-005` A line feed alone ends an empty line, which counts as one line. An empty file has zero lines, zero words and zero characters. A carriage return before the line feed is part of the line and is counted as a character, like any other code point. — by idea-owner; source https://github.com/pharzam/layup-uat-m2e2/issues/1#issuecomment-6343642161; the question: Does an empty line (a line feed alone) count as a line, does an empty file count 0 lines, and is a carriage return before the line feed part of the line or ignored?
7. `Q-006` Yes: the line feed is a code point and counts as a character. A byte order mark at the start of a file is a code point too and counts as one character; tally does not strip it. — by idea-owner; source https://github.com/pharzam/layup-uat-m2e2/issues/1#issuecomment-6343642161; the question: Do the line feed and any byte order mark count as characters?
8. `Q-007` A file is not text exactly when it is not valid UTF-8 (rule 6). A directory is an unreadable file under rule 5: tally prints a message on standard error with its name and the reason, adds no row, and ends with the exit code 1. — by idea-owner; source https://github.com/pharzam/layup-uat-m2e2/issues/1#issuecomment-6343642161; the question: Is "not text" the same as "not valid UTF-8" in behaviour 6, and when a directory is named on the command line, is it an unreadable file under behaviour 5 or something else?
9. `Q-008` The reference is any computer with 4 cores and a solid-state disk, with the file already in the cache of the operating system, for a file of 10 MiB of ASCII text with lines of about 80 characters. The time is the elapsed time of the whole process, from its start to its exit, so it includes start-up. — by idea-owner; source https://github.com/pharzam/layup-uat-m2e2/issues/1#issuecomment-6343642161; the question: Which computer (processor speed, disk, cache state) and which content of the generated file define the 2-second target, and does the elapsed time include process start-up?
10. `Q-009` Yes: the limit is the peak heap during the run, not the heap at the end. It is measured by sampling the heap in use (runtime.ReadMemStats, HeapAlloc) every 10 milliseconds during the count and taking the largest value. — by idea-owner; source https://github.com/pharzam/layup-uat-m2e2/issues/1#issuecomment-6343642161; the question: Is the target the peak heap during the run rather than the heap at the end, since a heap read after counting can miss the peak, and how is the peak to be measured?
11. `Q-010` Yes, the split is required: the counting package is a package count of the same Go module, separate from the package main of the command, and it holds the functions that count the lines, the words and the characters of a reader.
