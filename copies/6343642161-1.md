Q-001: A fixed order: lines, then words, then characters, whatever the order of the flags on the command line.
Q-002: Combined flags such as -lw are accepted and mean the same as -l -w. The name - is not standard input: tally treats it as a file named -. An unknown flag or wrong usage prints a usage message on standard error, counts nothing, and ends with the exit code 2.
Q-003: The other files are still counted. No row is printed for a file that is not valid UTF-8, and it adds nothing to the total; a message on standard error gives its name, and the exit code is 1 at the end. The check happens while the file is read, before its row would be printed: rows already printed for earlier files stay.
Q-004: The row for standard input has no name: it ends after the counts.
Q-005: A line feed alone ends an empty line, which counts as one line. An empty file has zero lines, zero words and zero characters. A carriage return before the line feed is part of the line and is counted as a character, like any other code point.
Q-006: Yes: the line feed is a code point and counts as a character. A byte order mark at the start of a file is a code point too and counts as one character; tally does not strip it.
Q-007: A file is not text exactly when it is not valid UTF-8 (rule 6). A directory is an unreadable file under rule 5: tally prints a message on standard error with its name and the reason, adds no row, and ends with the exit code 1.
Q-008: The reference is any computer with 4 cores and a solid-state disk, with the file already in the cache of the operating system, for a file of 10 MiB of ASCII text with lines of about 80 characters. The time is the elapsed time of the whole process, from its start to its exit, so it includes start-up.
Q-009: Yes: the limit is the peak heap during the run, not the heap at the end. It is measured by sampling the heap in use (runtime.ReadMemStats, HeapAlloc) every 10 milliseconds during the count and taking the largest value.
Q-010: Yes, the split is required: the counting package is a package count of the same Go module, separate from the package main of the command, and it holds the functions that count the lines, the words and the characters of a reader. The 90 percent target covers the package count only.
